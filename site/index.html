Agentic AI debug assistant · post-silicon validation

From 1.45 million log lines to a named root cause with the evidence attached.

SVLA-Agent streams multi-source silicon test logs, mines event templates, classifies and de-duplicates failures, clusters recurring families, retrieves similar historical incidents and asks Claude — or a deterministic rule-based agent — to pick the specific root cause and the next experiment to run. Every claim below is measured and reproducible.

What makes it different

Root cause, not just failure type

Twenty named root causes across six failure families. The agent scores each candidate against the evidence and quotes the tell-tale line that decided it — a slow fan, a refclk warning, a starved QoS credit.

Calibrated confidence

When Claude is wrong its confidence drops to 0.47; the rule-based agent stays at 0.77. A number you can actually triage on.

Streaming and fast

97 MB / 1.45 M events across 700 files parsed, template-mined and classified in 23 s on a laptop, about 64 k events/s, with flat memory.

Privacy first

E-mails, IPs, MACs, serials and credentials are redacted at parse time — before anything is indexed, prompted or written into a report.

Honest evaluation

Retrieval and root-cause metrics use a hold-out split: the index is built from 70% of runs and the rest are scored as unseen incidents. A failure can never retrieve itself.

Three front doors

A svla CLI, a FastAPI REST service and a Streamlit dashboard share one pipeline. Pluggable vector store and LLM provider. Docker image built in CI.

    Measured results

    Out-of-distribution: real supercomputer logs

    Recall transfers, precision does not: BGL logs many routine FATAL lines that operators never flagged, so severity alone over-flags on real data. Retrieval generalises — with zero domain knowledge the nearest past windows name the operators' alert tag most of the time, and fail mainly on components with a handful of examples. Method and per-family breakdown in docs/EVALUATION_OOD.md.

    The synthetic corpus above is closed-world. Each injected failure leaves a root-cause tell-tale 90% of the time; the remaining 10% exercises the retrieval and prior fallbacks, which is where the misses come from. Detection and typing are rule-based against the generator's own vocabulary and are expected to be perfect here — they will not be on real silicon logs. The structure (evidence → candidates → calibrated confidence → actions) is what carries over.
